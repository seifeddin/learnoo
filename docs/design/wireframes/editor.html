Flow 2 — Studio lesson editor (author)

Wireframe, not production UI. Studio is the React/TypeScript/TipTap app (LRN-003, in progress separately). Block types below are taken from the current experimental contract in docs/fixtures/README.md; this page does not change that schema. Lesson text is placeholder.

Covers: editing a draft, the changes-requested return path, submitted (immutable) state, save conflict and submit validation errors, a narrow-screen layout, and who can open the editor.

2.1 Desktop — editing a draft

Annotations

  1. 1Back to the teacher's lesson list (Flow 5, teacher view).
  2. 2Preview uses the canonical Go renderer (same output as the reader, Flow 1), with phone/desktop width toggle.
  3. 3Submit is the only primary action. It opens a confirmation: "Après soumission, cette révision ne pourra plus être modifiée." Validation errors appear as in 2.4.
  4. 4role="toolbar" with roving tabindex: one Tab stop, arrow keys move between buttons (mirrored in RTL), Escape returns to the document. Buttons map 1:1 to allowed block types; nothing outside the contract is offered.
  5. 5Document area. Each block shows a small type tag while editing. Formula blocks show TeX source next to the rendered result; render errors are shown in text inside the block, never silently dropped.
  6. 6Metadata panel after the document in Tab order. Metadata is part of the reviewed snapshot (title, objective, prerequisites, curriculum assignment).

Save status is an aria-live="polite" region. Autosave uses version-checked saves (2.4 conflict).

Coordinate with #3 Keyboard shortcuts (e.g. Ctrl+B, an inline-math shortcut) and the exact block-language control are proposals for the TipTap prototype, not decisions.

2.2 Changes requested — author returns

Rules

  • The reviewer's comment is mandatory for this state (Flow 3), so this banner is never empty.
  • "Créer la révision corrigée" creates the successor draft based on revision 2's content; the editor (2.1) then shows the comment in a collapsible side note while editing.
  • Only one open draft/review candidate per lesson: if a successor draft already exists, the button becomes "Continuer la révision 3".
  • The currently published revision (if any) stays visible to students throughout.

2.3 Submitted — in review (immutable)

  • Immutability is a server rule; the UI simply does not offer edit controls.
  • Email notifications are deferred (M2); status is visible on the teacher dashboard.
  • Open Whether an author may cancel a pending submission is not specified; not shown.
