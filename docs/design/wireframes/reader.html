Flow 1 — Student lesson reader (mobile first)

Wireframe, not production UI. All lesson text is grey placeholder bars or the labelled formula z = 3 + 2i; no teaching content is invented. Author/reviewer names are placeholders. The reader is the Go server-rendered page; these frames do not change the renderer.

Covers: signed-in student (FR interface), Arabic interface (RTL chrome around a French lesson), visitor gate, unavailable lesson, report-an-error, and the desktop layout. Numbers in black circles are the keyboard / screen-reader order.

1.1 Mobile, French interface, signed-in student

Annotations

  1. 1Skip link (first Tab stop, visible on focus) then logo/home. Header stays short (≤ 56px) and scrolls away; no sticky toolbar competing with text on small screens.
  2. 2Title search (MVP: basic title search, accent-insensitive). Opens a full-screen search page, not an overlay.
  3. 3Menu exposes the hierarchy section → subject → chapter → lesson. aria-expanded toggles; Escape closes and returns focus to the button.
  4. 4Breadcrumb gives subject/chapter context before the h1. Author and reviewer credit ships in M1 (placeholders here). The amber "Exemple non relu" chip only appears on technical fixtures and never on published lessons.
  5. 5Bookmark toggle: aria-pressed, label changes to "★ Enregistré". Bookmarks reference the stable lesson identity, so title changes do not break them.
  6. 6Honest video placeholder when the teacher has not selected a video. When present: YouTube embed after the written explanation it supports, plus a plain link "Ouvrir sur YouTube".
  7. 7Worked solutions are native <details>: keyboard (Enter/Space) and no-JS friendly; collapsed by default so students try first.
  8. 8Report an error (M1, LRN-015) opens the form in 1.5. Placed after the content, before chapter navigation.
  9. 9–10Previous/next lesson in chapter order. Full-width 44px targets in the thumb zone; the primary action is "next".

Formulas: KaTeX output is LTR-isolated and scrolls horizontally inside its block instead of overflowing the page. Body text 17px / 1.7 line-height per DESIGN.md.

1.2 Mobile, Arabic interface (RTL chrome, French lesson)

RTL rules shown

  1. AInterface language is independent of lesson language. Chrome (header, breadcrumb separators, bookmark label, footer) mirrors; the French lesson keeps dir="ltr" and left-aligned text.
  2. BLogical CSS only (margin-inline-*, inset-inline-*, border-inline-start). The Arabic explanation rule sits on the inline-start edge in both directions.
  3. CDirectional arrows mirror: "previous" points right (→) in RTL, "next" points left (←); arrows are separate aria-hidden items so they sit on the outer edge. The breadcrumb "›" is a bidi-mirrored glyph and flips automatically. Order stays previous → next in DOM, so Tab order follows visual reading direction.
  4. DFrench terms inside Arabic text and formulas inside Arabic paragraphs are wrapped in <bdi> / dir="ltr" so punctuation does not jump.
  5. EArabic uses its fallback font stack, normal letter-spacing and 1.9 line-height (token --learnoo-leading-arabic).

Unverified Arabic interface strings here are placeholders and need review by a native speaker before LRN-023.

1.3 Visitor (not signed in)

Notes

  • Visitor sees title, chapter context and credit, but no lesson body (no partial preview is assumed; that would be a product decision).
  • During the internal pilot registration is invitation-only: "Créer un compte" becomes "Inscription sur invitation" with an explanation (see Flow 4).
  • Return-to URL must be validated server-side as a same-site path (open-redirect safety).

1.4–1.5 Error and empty states

State rules

  • Error summary receives focus on failed submit, links to the field; field keeps entered text (GOV.UK pattern, DESIGN.md).
  • Network failure while loading: server-rendered page means the browser's own error page; on form submit failure, keep input and show "Impossible d’envoyer pour le moment. Réessayez."
  • KaTeX failure: readable source fallback inside the formula block (already exercised by failure.json).

1.6 Desktop

Desktop deltas

  • Search field inline in the header; bookmarks and account menu visible instead of hidden in the menu.
  • Chapter navigation (5) comes before the lesson in DOM so screen-reader users get context; the skip link jumps past it straight to 6. aria-current="page" marks the open lesson.
  • In RTL the side column moves to the right automatically via the grid's logical order; no separate layout.
  • Role-specific header entries (Studio, Relecture, Administration) are defined in Flow 5 (dashboard).
