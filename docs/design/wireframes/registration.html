Flow 4 — Student registration and sign-in

Wireframe, not production UI. Several policies are still open (CAHIER_DES_CHARGES §3.3): privacy policy, retention and deletion, email verification, and how minors register. Those parts are marked Open decision and must not be implemented as shown without a recorded decision.

Covers: invited pilot registration (M1), public self-registration (M3), validation errors, sign-in with enumeration-safe errors and rate limiting, the Arabic interface, and desktop.

4.1 Internal pilot — invitation link (M1)

Annotations

  1. 1–2Interface language switch is reachable before the form; it changes the UI language only.
  2. 3Minimal personal data: one display name, no surname, school, phone, birth date or photo.
  3. 4Password with show/hide toggle (aria-pressed); input stays LTR in both interfaces. The exact length rule belongs to LRN-005.
  4. 5Optional BAC section, skippable; only used for navigation shortcuts.
  5. 6Consent wording depends on the privacy policy, which does not exist yet.
  6. 7On success the student lands on the dashboard (Flow 5) or the lesson they came from.

4.2 Public self-registration (M3) with validation errors

  • Error summary receives focus; each link moves to its field; entered values are kept except the password.
  • "Email already used" is never shown on the form (account enumeration). The existing owner receives an email instead. This depends on the email-verification decision.
  • Self-registration abuse controls (rate limits, possibly a challenge) belong to LRN-022 and are not drawn.

4.3 Sign in, errors, rate limit

  • One generic message for unknown email and wrong password (enumeration-safe, LRN-005).
  • Password recovery always answers "Si un compte existe pour cette adresse, un e-mail a été envoyé."
  • Session is rotated on sign-in; this has no visible UI.

4.4 Arabic interface

  • Labels, hints and errors align to the inline start (right). Email and password values are typed LTR; the display name follows the text the student types (dir="auto" in implementation).
  • Unverified Arabic copy needs native-speaker review (LRN-023).

4.5 Desktop

No two-column form on desktop: one column keeps the Tab order identical to the visual order in both directions.
